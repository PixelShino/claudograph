# tg-bridge — мультисессионный Telegram-мост для Claude Code

Один бот, настоящие инлайн-кнопки, N параллельных сессий (вкладок) Claude Code —
без путаницы. Заменяет официальный `telegram`-плагин, чей `reply` не умеет кнопок
и чей поллер позволяет получать входящие только одной сессии за раз.

## Зачем

Telegram Bot API разрешает **ровно один** `getUpdates` на токен. Официальный
плагин поэтому даёт входящие только последней запущенной вкладке — 4 вкладки
путаются. Здесь единственный **демон** держит этот один поллинг, а вкладки
общаются с ним по локальному HTTP. Нажатие кнопки несёт `handle` сессии в
`callback_data`, поэтому тап всегда возвращается в ту вкладку, что кнопку послала.

## Как устроено

```
Telegram (1 бот) ──getUpdates(исходящий)──► daemon.ts (1 процесс)
                                              │  http://127.0.0.1:8787 (loopback)
                    ┌──────────────┬──────────┴───────┐
              session-mcp #1   session-mcp #2   session-mcp #N   ← по одному на вкладку
              (Claude Code)    (Claude Code)    (Claude Code)
```

- **daemon.ts** — общий. Поллинг + `sendMessage`/`edit`/`react`, реестр
  `handle → сессия`, роутинг тапов (по `callback_data`) и свайп-reply (по карте
  `message_id → сессия`). Токен и allowlist берёт из
  `~/.claude/channels/telegram/` (пейринг офиц. плагина переиспользуется).
- **session-mcp.ts** — stdio-MCP, спавнится Claude Code в каждой вкладке. Даёт
  инструменты `send` (текст + кнопки), `edit`, `react`; при старте поднимает
  демон если его нет, регистрируется, long-poll'ит свои входящие и превращает их
  в `<channel>`-сообщения. Проксирует permission-запросы → кнопки Allow/Deny.

Наружу уходит только исходящий поллинг к `api.telegram.org`. Всё «сервер↔сервер»
— на `127.0.0.1`. **Туннель не нужен** (мы не webhook).

## Подключение (cutover)

1. **Отключить официальный плагин** (иначе война за токен, `409 Conflict`):
   в Claude Code — `/plugin` → Manage → `telegram` → Disable.
2. **Прописать наш MCP в user-scope** (подхватят и CLI, и VS Code):
   ```
   claude mcp add tg-bridge -s user -- bun "C:\Users\Админис\.claude\tg-bridge\session-mcp.ts"
   ```
   Опционально ярлык вкладки: добавить `-e TG_BRIDGE_LABEL=<имя>`.
3. **Перезапустить** сессии Claude Code. С этого момента в каждой вкладке есть
   инструмент `send` с кнопками.

## Проверка

```
bun test-routing.ts      # изоляция очередей сессий, без реального Telegram
```

## Гочи

- `callback_data ≤ 64 байта` → `handle` короткий (`h0`,`h1`…), ключ кнопки — тоже.
- Свободный текст роутится свайп-reply'ем; reply без свайпа уходит в последнюю
  активную вкладку с флагом `ambiguous` (Claude переспросит перед опасным).
- Тап по кнопке мёртвой/перезапущенной вкладки → «Сессия закрыта».
- Демон single-instance по биндингу порта 8787; переживает перезапуск вкладок.
- Секрет `state/daemon.secret` (0600) гейтит локальный HTTP от чужих процессов.
