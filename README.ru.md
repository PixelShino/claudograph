`claudograph` — мост между [Claude Code](https://docs.claude.com/en/docs/claude-code) и Telegram. Он позволяет **нескольким вкладкам Claude Code** общаться с тобой через **одного** Telegram-бота без путаницы: у каждой вкладки свой диалог, работают инлайн-кнопки, ответы возвращаются в нужную вкладку, а сообщения приходят как **нативные Telegram Rich Messages** (настоящие заголовки, таблицы, сворачиваемые блоки). Может присылать **скриншоты**, показывать **живую строку прогресса** и — с экспериментальной фичей *channels* — **будить спящую вкладку**, когда ты жмёшь кнопку с телефона.

Он заменяет официальный плагин `telegram`, чей `reply` не умеет кнопки, а поллер даёт входящие только **одной** вкладке (Telegram разрешает один `getUpdates` на токен).

> **Про имя:** Telegram назван в честь *телеграфа*. `claude` + `telegraph` = **claudograph** — прибор, передающий сообщения Claude по проводам.

## Зачем

Telegram Bot API разрешает **ровно один** long-poll `getUpdates` на токен. Запусти четыре вкладки Claude Code с официальным плагином — и ответы получает только последняя запущенная, остальные глохнут.

`claudograph` решает это **одним общим демоном**, который держит этот единственный поллинг. Все вкладки общаются с ним по локальному HTTP. Нажатие кнопки несёт `handle` вкладки в `callback_data`, поэтому тап всегда возвращается в ту вкладку, что кнопку послала. Наружу уходит только исходящий поллинг к `api.telegram.org`; всё «сервер↔сервер» — на `127.0.0.1`. **Ни туннеля, ни webhook, ни входящего порта.**

## Возможности

- 🧵 **Одна тема Telegram на вкладку** — каждая вкладка Claude Code = свой нативный *топик* (тред), параллельная работа не смешивается. Опционально, нужен Threaded Mode.
- 🔘 **Настоящие инлайн-кнопки** — присылай варианты для тапа; тап возвращается в ту же вкладку.
- 🎨 **Нативные Rich Messages** — пишешь обычный GFM-markdown, он рендерится структурно (заголовки, таблицы с рамками, чек-листы, сворачиваемые `<details>`, спойлеры, `$LaTeX$`). Автофолбэк на MarkdownV2 → plain.
- 📸 **Скриншоты и картинки** — отправка локального изображения (например, скрина страницы) прямо в тему вкладки.
- 🎤 **Голосовые на вход** — можно надиктовать вместо набора: голосовые, аудио и видеокружки расшифровываются через любой OpenAI-совместимый STT и доходят до Claude текстом. Опционально; нужен `STT_API_KEY`.
- ⏳ **Живая строка прогресса** — одно сообщение, которое само правится по мере работы инструментов.
- ✅ **Зеркало финального ответа** — ответ каждого хода автоматически уходит в Telegram (выжимка + сворачиваемый полный текст), без твоего участия.
- 📲 **Пробуждение по тапу** — с экспериментальным флагом *channels* тап с телефона будит спящую терминальную сессию.
- 🔒 **Только локальный IPC** — loopback-API закрыт секретом на каждый запуск; токен бота не покидает конфиг машины.

## Как устроено

```
          Telegram (один бот)
                │  getUpdates (исходящий long-poll)
                ▼
        ┌───────────────┐        state/threads.json
        │   daemon.ts   │◄──────  state/daemon.secret
        │  один процесс │         (владеет Bot API + состоянием)
        └───────┬───────┘
                │  http://127.0.0.1:8787  (loopback, за секретом)
    ┌───────────┼────────────┬───────────────┐
    ▼           ▼            ▼                ▼
session-mcp  session-mcp  stop-notify.py  progress-notify.py
 (вкладка 1) (вкладка 2)  (Stop-хук)      (PostToolUse-хук)
  Claude       Claude     финальный ответ живой прогресс
```

Три части:

1. **`daemon.ts`** — общий процесс (поднимается первой вкладкой). Держит единственный поллинг Telegram, Bot API и всё состояние (`threads.json`, секрет). Отдаёт loopback-HTTP API: `/register`, `/poll`, `/send`, `/edit`, `/react`, `/send-photo`, `/ensure-thread`, `/rename-thread`, `/permission`. Роутит тапы (по `callback_data`) и входящие (по теме → вкладка, либо свайп-reply).

2. **`session-mcp.ts`** — stdio-[MCP](https://modelcontextprotocol.io), спавнится Claude Code **на каждую вкладку**. При старте поднимает демон если надо, регистрируется, создаёт свою тему, long-poll'ит входящие (превращая их в `<channel>`-сообщения). Даёт Claude инструменты `send`, `edit`, `react`, `send_photo`, `rename_thread`.

3. **Два Python-хука** (прописаны в `settings.json` Claude Code), которые шлют в Telegram **напрямую** (не через демон, поэтому переживают мёртвый демон) — см. [Хуки](#хуки--что-они-инжектят).

## Требования

- [**Bun**](https://bun.sh) ≥ 1.0 (запускает TS-демон и MCP-сервер напрямую)
- **Python** ≥ 3.9 (два хука-нотификатора; только стандартная библиотека)
- **Claude Code** (CLI или расширение VS Code)
- **Токен Telegram-бота** от [@BotFather](https://t.me/botfather)
- Твой **числовой user id** в Telegram (спроси у [@userinfobot](https://t.me/userinfobot))

## Установка

С нуля до рабочего моста. Пути ниже предполагают, что репо лежит в `~/.claude/claph` — поправь, если клонировал в другое место.

### 1. Создай бота и получи токен

В Telegram напиши [@BotFather](https://t.me/botfather) → `/newbot` → пройди шаги → скопируй токен (вида `123456789:AA...`).

### 2. Клонируй и установи

```bash
git clone https://github.com/PixelShino/claudograph ~/.claude/claph
cd ~/.claude/claph
bun install
```

### 3. Токен + allowlist

Мост читает токен и allowlist из `~/.claude/channels/telegram/` (формат общий с офиц. плагином — можно переиспользовать пейринг). Создай:

`~/.claude/channels/telegram/.env`
```
TELEGRAM_BOT_TOKEN=123456789:AA-твой-токен
```

`~/.claude/channels/telegram/access.json`
```json
{ "allowFrom": ["<твой-telegram-user-id>"] }
```

Общаться с ботом могут только id из `allowFrom` — остальные игнорируются. **Бот только твой.**

### 4. Пропиши MCP-сервер (один раз, user-scope)

```bash
claude mcp add claudograph -s user -- bun "~/.claude/claph/session-mcp.ts"
```

Подхватят и CLI, и расширение VS Code. Чтобы у вкладки было фиксированное имя (и своя тема) — задай env при запуске, см. [Нативные треды](#нативные-треды-одна-тема-на-вкладку).

### 5. Подключи хуки (зеркало ответа + прогресс)

Добавь в `~/.claude/settings.json` (создай ключ `hooks`, если его нет):

```json
{
  "hooks": {
    "PostToolUse": [
      { "hooks": [{ "type": "command", "command": "python \"$HOME/.claude/claudograph/progress-notify.py\"" }] }
    ],
    "Stop": [
      { "hooks": [
        { "type": "command", "command": "python \"$HOME/.claude/claudograph/progress-notify.py\"" },
        { "type": "command", "command": "python \"$HOME/.claude/claudograph/stop-notify.py\"" }
      ] }
    ]
  }
}
```

Хуки подхватываются на лету — перезапуск для них не нужен.

> **Windows:** пиши `pythonw` вместо `python`. `python.exe` — консольное приложение,
> поэтому на каждый вызов хука мигает окно терминала; `pythonw.exe` — тот же
> интерпретатор без консоли. Хуки сюда ничего не пишут в stdout, так что ничего
> не теряется.

### 6. (Опц.) Голосовые — расшифровка речи

Claude читает текст, а не звук. Укажи мосту любой OpenAI-совместимый эндпоинт
`/audio/transcriptions` — и голосовые, аудиофайлы и видеокружки будут приходить
расшифрованными; без него они придут как `🎤 (голосовое, расшифровать не удалось: …)`,
а не пропадут молча. Добавь в тот же `channels/telegram/.env`, где лежит токен:

```bash
STT_API_KEY=gsk_...                              # обязательно
STT_BASE_URL=https://api.groq.com/openai/v1      # по умолчанию https://api.openai.com/v1
STT_MODEL=whisper-large-v3-turbo                 # по умолчанию whisper-1
STT_LANGUAGE=ru                                  # по умолчанию ru
```

У [Groq](https://console.groq.com/keys) есть бесплатный тариф, и он самый быстрый
из облачных; `whisper-1` от OpenAI работает на дефолтных настройках. Файлы больше
25 МБ отсекаются до загрузки. Учти: **не каждый OpenAI-совместимый шлюз проксирует
аудио** — provod.ai, например, отдаёт на этот роут 404.

### 7. Отключи официальный плагин (иначе война за токен)

Два поллера на одном токене конфликтуют (`409 Conflict`). В Claude Code: `/plugin` → Manage → `telegram` → **Disable**. Затем перезапусти вкладки.

### 8. (Опц.) Пробуждение по тапу

Чтобы **тап с телефона будил спящую терминальную сессию**, запускай Claude Code с экспериментальным флагом channels:

```bash
claude --dangerously-load-development-channels server:claudograph
```

(«dangerous» тут лишь пропускает allowlist research-preview.) Увидишь тусклую строку старта `Channels (experimental) messages from server:claudograph inject directly in this session`. **Работает только при запуске из терминала**, не в панели расширения VS Code.

### 9. (Опц.) Нативные треды — Threaded Mode

Чтобы получить **одну тему на вкладку**, включи в [@BotFather](https://t.me/botfather) → твой бот → *Bot Settings* → *Threaded Mode* → **On** (и *Disallow users to create new threads* → On, чтобы темы создавал только бот). Про плату: Telegram берёт 15% только с **покупок** Telegram Stars внутри бота (ToS §6.2.6) — бот, который ничего не продаёт, платит ноль.

## Использование

Внутри подключённой вкладки у Claude есть инструменты:

| Инструмент | Что делает |
|------------|------------|
| `send` | Отправить сообщение. `format` по умолчанию — **rich markdown**; `buttons: [{key, label}]` для тапов; `format: 'text'` для plain. |
| `edit` | Править сообщение, которое эта вкладка отправила (для стриминга/прогресса). |
| `react` | Реакция эмодзи на твоё сообщение. |
| `send_photo` | Отправить локальную картинку (`path` + опц. `caption`) — например, скрин — в тему вкладки. |
| `send_album` | Отправить коллаж: 2–10 локальных картинок одним альбомом Telegram (`paths` + опц. `caption`). |
| `rename_thread` | Переименовать тему этой вкладки. |

Ты просто пишешь боту. Текст роутится в нужную вкладку; тап по кнопке возвращается в ту, что спросила.

## Нативные треды (одна тема на вкладку)

Каждая вкладка привязана к теме Telegram по **метке** = env `CLAPH_LABEL`, либо имени рабочей папки, если не задано. Демон создаёт-или-переиспользует тему при старте и пишет `state/threads.json`; хуки читают его, чтобы слать в нужную тему.

- **Одна вкладка на проект** → метка = имя папки автоматически. Ничего настраивать не надо.
- **Две вкладки в одном репо** → задай им разные метки при запуске, чтобы получить разные темы:
  ```bash
  CLAPH_LABEL=chat claude          # bash
  $env:CLAPH_LABEL='chat'; claude  # PowerShell
  ```
  Без разных меток вкладки одного репо **делят** одну тему (by design). Git-worktree'ы отличаются путём → разделяются автоматически.
- **Закрытие вкладки** → её тема уходит в 💤 *idle*, когда закрылась последняя вкладка этой метки; история сохраняется, ничего не удаляется. Переоткрытие той же метки переиспользует ту же тему (🟢 active). Дубли не плодятся.

> Важно: env-переменная задаётся **при запуске** (и MCP-сервер, и хуки читают её тогда). Панель расширения VS Code не умеет per-tab env — для разных меток запускай из терминала.

## Хуки — что они инжектят

«Автоматика» моста живёт в двух Python-хуках, которые Claude Code запускает на события. Они шлют в Bot API **напрямую** (не через демон), поэтому работают даже если демон мёртв, и не вызывают запрос разрешения.

- **`stop-notify.py`** (`Stop`-хук) — после каждого хода зеркалит финальный ответ Claude в твою тему. Делит ответ на короткую **выжимку** + сворачиваемый `<details>` с полным текстом (явный маркер `<!-- tg: … -->` в ответе задаёт выжимку; иначе берётся первый абзац). Дедуплицирует: если Claude уже отправил интерактивное сообщение в этом ходе, хук молчит вместо дубля.
- **`progress-notify.py`** (`PostToolUse` + `Stop`) — держит **одно** живое сообщение «что делаю сейчас», которое само правится по мере работы инструментов (с троттлингом; появляется, только когда ход набрал вес), и удаляет его на `Stop`. Ключ — session id, поэтому вкладки не сталкиваются.

Оба вычисляют метку вкладки так же, как `session-mcp`, — поэтому все трое согласны, в какую тему слать.

## Гочи

- `callback_data ≤ 64 байта` → `handle` короткий (`h0`, `h1`…), ключ кнопки — тоже.
- Демон single-instance по биндингу порта `8787`; переживает перезапуск вкладок. Если убить — следующая вкладка поднимет новый (in-memory handle'ы сбросятся, вкладки перерегистрируются).
- `state/daemon.secret` (0600) гейтит loopback-HTTP от чужих локальных процессов.
- Удаление темы в Telegram оставляет устаревшую запись в `threads.json`; демон деградирует к плоскому чату, пока запись не почищена или тема не пересоздана.
- Кириллица на Windows: хуки читают stdin как UTF-8 байты (иначе кодировка консоли ломает текст).
- **Одна машина-хост на токен бота.** Telegram разрешает только одного потребителя `getUpdates`, поэтому вторая машина со своим демоном на том же токене проигрывает гонку: одна поллит, вторая бесконечно ретраит `409 Conflict` и не получает ничего. Демон живёт на каждой машине отдельно, а его биндинг порта защищает только от второго демона на *той же* машине. Чтобы работать с ноутбука и десктопа одновременно, нужен либо второй бот (свой токен, свои темы), либо один общий демон, к которому вторая машина ходит по сети (`CLAPH_PORT` настраивается, `HOST` намеренно loopback). Переход на webhook сам по себе это не снимает — Telegram доставляет ровно на один URL, так что для нескольких машин всё равно нужен релей перед ними.

## Структура проекта

```
claudograph/
├── daemon.ts            # общий демон: поллинг, Bot API, состояние, роутинг
├── session-mcp.ts       # per-tab MCP-сервер (инструменты + входящие)
├── shared.ts            # конфиг, типы протокола, хелперы состояния тредов
├── format.ts            # GFM → MarkdownV2 фолбэк
├── stop-notify.py       # Stop-хук: зеркало финального ответа
├── progress-notify.py   # PostToolUse+Stop хук: живая строка прогресса
├── test-routing.ts      # тест изоляции роутинга
├── *.test.ts / test_*.py# юнит-тесты
└── state/               # рантайм (в gitignore): секрет, threads.json, логи
```
