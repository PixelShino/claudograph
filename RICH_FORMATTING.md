# Rich Messages — как я форматирую сообщения в Telegram

Инструкция самому себе. Написана 2026-07-17 после того, как пользователь
подтвердил (кнопка `rich_full`), что его Android рисует Rich Messages полностью:
настоящие таблицы с рамками, сворачиваемые блоки, спойлеры.

## TL;DR

Пишу **обычный GFM-markdown** и отправляю с `format:'markdown'` через claph
`send`/`edit`. Мост шлёт его как **нативный Rich Message** (`sendRichMessage`,
Bot API 10.1+) — реальные заголовки, таблицы, списки, сворачиваемые `<details>`,
цитаты, спойлеры, формулы. Рендерится структурно на современных клиентах.
Если сервер отклонит — авто-фолбэк на классический MarkdownV2, затем plain.
**Экранировать ничего не надо** (в отличие от MarkdownV2): пишу markdown как есть.

Лимит — 32768 символов в ОДНОМ сообщении (без чанкинга).

## Как слать

- Инструмент `send({ text, format:'markdown' })` — новое сообщение.
- Инструмент `edit({ message_id, text, format:'markdown' })` — правка (в т.ч.
  для прогресса; см. `progress-notify.py`).
- Дефолт формата — `text` (plain). Rich включаю **явно** через `format:'markdown'`.
- ГОТЧА этой сессии: закэшированная схема тула могла знать только
  `text`/`markdownv2`. Если `markdown`/`rich` отклоняется клиентом — шлю через
  скрипт напрямую в демон (`/send` с `format:'rich'`) или генерю заранее.

## Диалект (markdown-поле)

Проверено по типам `@grammyjs/types/rich.d.ts` (authoritative).

### Инлайн
```
**bold**  __bold__      *italic*  _italic_
~~strikethrough~~        `inline code`
==marked==               ||spoiler||
[текст](https://…)  [почта](mailto:a@b.c)  [тел](tel:+7…)
[юзер](tg://user?id=123)
$x^2 + y^2$              (инлайн-формула LaTeX)
```

### Заголовки (h1–h6, рендерятся РАЗНЫМ размером — не просто жирным!)
```

## H2
### H3
```

### Списки
```
- пункт        (или *  или +)
1. нумерованный
- [ ] задача не сделана
- [x] задача сделана
```

### Цитата
```
> Строка цитаты
> Продолжение
```

### Код-блок (с языком)

```
print('hello')
```

### Таблица (НАСТОЯЩАЯ, с рамками и выравниванием)
```
| Метрика | Значение | Статус |
|:--------|--------:|:------:|
| Скорость | **42** мс | готово |
| Отказы  | 18%      | ||секрет|| |
```
`:---` слева, `---:` справа, `:--:` по центру. До 20 столбцов.
В ячейках можно markdown (жирный, спойлер, `код`, `<sup>`).

### Сворачиваемый блок (details)
```
<details open><summary>Заголовок с **markdown**</summary>

### Внутри — обычный markdown
- список
- _курсив_

</details>
```
`open` = развёрнут по умолчанию; без него — свёрнут. Внутри — полный markdown.
Пустая строка после `<summary>` и перед `</details>` обязательна.

### Формулы
```
$инлайн$        $$блочная$$
```
Блок ```` ```math ```` … ```` ``` ```` — тоже формула.

### Сноски
```
Текст со сноской[^1].

[^1]: Определение сноски.
```

### Медиа (только HTTP/HTTPS-URL, отдельными блоками)
```
![](https://…/photo.jpg "Подпись")
![](https://…/video.mp4)
```
Коллажи/слайдшоу — `<tg-collage>…</tg-collage>`, `<tg-slideshow>…`.

### Разделитель
```
---
```

## HTML-путь (альтернатива, больше контроля)

`InputRichMessage` принимает `{ html }` вместо `{ markdown }`. Пример из статьи
(Amvera, habr 1055670): `<h1>`, `<mark>`, `<table bordered striped><caption>…`,
`<tr><th>…`, `<details><summary>…`. Использую markdown по умолчанию (проще);
HTML — если нужен `bordered striped`, `<caption>`, точные вложенные теги
(`<sup>`,`<sub>`,`<ins>`,`<u>`,`<tg-spoiler>`).

## Лимиты

## Стриминг (нативный)

`sendRichMessageDraft(chat_id, draft_id, {markdown})` — эфемерный черновик ~30с,
для стрима ответа LLM пока он генерится; в конце ОБЯЗАТЕЛЬНО финализировать
через `sendRichMessage`, иначе черновик исчезнет. Сложнее (нужен `draft_id` из
контекста апдейта). Сейчас «процесс идёт» закрыт проще — `progress-notify.py`
редактирует одно сообщение по мере тулов. Черновик — на будущее, если захочется
токен-за-токеном.

## Когда что применять (не переусердствовать)

- **Заголовки** — структура длинного ответа (H2/H3). Не пихать в короткое.
- **Таблицы** — только табличные данные (метрики, сравнения). Не для списка из 2
  строк.
- **`<details>`** — длинная/необязательная деталь (полный лог, сырые числа),
  чтобы не раздувать сообщение. Итог — снаружи, подробности — под своротом.
- **Спойлеры** — редко (секрет/ответ-загадка), не для акцента.
- **Формулы** — если правда математика.
- Короткий ответ/статус-строка — plain `text`, без rich.

## Гейт качества перед отправкой rich

1. Экранирование НЕ трогаю (rich markdown, не MarkdownV2).
2. Таблица: у separator-строки столько же `|`, сколько в шапке.
3. `<details>`: пустые строки вокруг тела.
4. Уложился в 32768 — иначе фолбэк начнёт чанкить.
5. Не превратил короткий ответ в простыню заголовков и таблиц.
